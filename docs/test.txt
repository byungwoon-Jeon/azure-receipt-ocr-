1. 이미지 정제 기능 - Gemini의 이미지 입력 및 내부 토큰화 기능
======================================================================
[공식 홈페이지]
제목: 이미지 이해 (Image understanding) / Google Cloud 공식 문서
URL: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/image-understanding?hl=ko

[홈페이지에서 캡처할 내용]
캡처명: 01_이미지_토큰화.png
페이지 내 Ctrl+F 검색어: 이미지 토큰화
캡처 범위:
  - '이미지 토큰화' 절의 제목
  - 'Gemini 3 모델 ... 가변 시퀀스 길이 ... 이전 모델에서 사용된 팬 앤 스캔 ...' 설명
  - '이미지 및 PDF 입력의 미디어 해상도를 지정할 수 있으며 ... 토큰화되는 방식 ...' 설명
  - 가능하면 MEDIA_RESOLUTION_HIGH/MEDIUM/LOW 등 해상도 설명

[의미 / 기술 설명]
Gemini는 이미지 입력에 대해 자체 이미지 토큰화 및 해상도에 따른 입력 표현 처리 기능을 제공한다.
따라서 문서를 인식하기 위해 자체 이미지 특성 추출기를 별도로 개발해야 하는 구조는 아니다.
※ 이것은 내부 모델 입력 처리에 대한 근거이며, 노이즈 제거·기울기 보정·명암 개선이 자동 수행된다는 근거는 아니다.

[제출 설명 - 붙여 넣기용]
"Google Cloud 공식 기술문서에 따르면 Gemini 멀티모달 모델은 입력 이미지의 토큰화 및 미디어 해상도에 따른 처리 기능을 제공한다. 본 프로젝트는 해당 모델의 이미지 이해 기능을 활용해 문서 정보를 추출하도록 구성하였으며, 별도의 이미지 인식 모델을 구축하지 않았다. 독립적인 화질 개선 알고리즘(노이즈 제거, 기울기 보정 등)의 구현 여부는 별도 범위로 구분한다."

[추가 실제 프로젝트 증빙 권장]
- 이미지 파일 입력 API 요청 코드 또는 로그 (MIME: image/jpeg 또는 image/png)
- 해당 이미지의 데이터 추출 성공 화면 또는 JSON 결과
- 로그 캡처 시 문서 내 개인정보, 인증 토큰, 프로젝트 비밀정보 마스킹

2. 이미지 정제 기능 - 이미지 입력 요구 품질 및 주의사항(참고 증빙)
======================================================================
[공식 홈페이지]
제목: 이미지 이해 (위의 1번과 동일)
URL: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/image-understanding?hl=ko

[홈페이지에서 캡처할 내용]
캡처명: 02_이미지_입력권장사항.png
페이지 내 Ctrl+F 검색어: 권장사항
캡처 범위:
  - '권장사항' 절
  - '해상도가 높은 이미지를 사용하면 결과가 더 좋습니다.'
  - '이미지를 적절한 방향으로 회전한 후에 프롬프트에 추가하세요.'
  - '흐릿한 이미지는 사용하지 마세요.'

[의미 / 기술 설명]
공식 문서는 입력 이미지 자체의 품질 확보를 권장한다.
따라서 해당 페이지를 'Vertex가 이미지 회전 및 노이즈 제거를 자동 수행한다'는 주장에 사용하면 안 된다.
별도 정제 개발을 수행하지 않은 근거로 제출하려면, 운영 데이터 품질이 충분하고 실측 인식 성능이 요구 수준을 충족했다는 프로젝트 증빙이 추가로 필요하다.

[제출 설명 - 붙여 넣기용]
"Google Cloud는 멀티모달 이미지 처리 기능과 함께 입력 이미지의 해상도 및 방향 등 품질 확보를 권장한다. 본 프로젝트는 별도 화질 개선 모듈의 필요성을 실제 대상 문서의 품질 및 인식 결과를 기준으로 검토하였다."

[주의]
이 화면은 '별도 이미지 정제가 무조건 불필요하다'는 증빙이 아니라, 기능 범위와 품질 기준을 정확히 보여주는 보조자료다. 검수 자료에는 필요 시 선택적으로 포함한다.

3. 데이터 포맷 표준화 - PDF 원본 직접 입력 지원 (핵심 증빙)
======================================================================
[공식 홈페이지]
제목: 문서 이해 (Document understanding) / Google Cloud 공식 문서
URL: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/document-understanding?hl=ko

[홈페이지에서 캡처할 내용]
캡처명: 03_PDF_직접입력_API.png
페이지 내 Ctrl+F 검색어: 요청에 문서 추가
캡처 범위:
  - '문서(PDF 및 TXT 파일)를 Gemini 요청에 추가...'라는 문서 첫 설명
  - '요청에 문서 추가' → 'Python' 코드 예시
  - 아래 핵심 코드가 보이게 캡처:
      model_id = "gemini-3.5-flash"
      pdf_file = Part.from_uri(
          file_uri="gs://cloud-samples-data/generative-ai/pdf/1706.03762v7.pdf",
          mime_type="application/pdf",
      )
      response = client.models.generate_content(
          model=model_id,
          contents=[pdf_file, prompt],
      )
  - 화면 크기 때문에 길다면 문서 소개와 Python 코드 캡처를 2장으로 나눠도 됨

[의미 / 기술 설명]
Vertex AI Gemini는 PDF를 application/pdf 형식으로 직접 요청에 포함할 수 있다.
모든 PDF를 PNG/JPEG 이미지로 변환하는 과정은 API 사용의 필수 선행 단계가 아니다.
이는 입력 데이터 포맷을 단일 이미지 포맷으로 강제하지 않아도 된다는 직접적인 공식 근거다.

[제출 설명 - 붙여 넣기용]
"Google Cloud의 Document understanding 공식 문서 및 Python API 예시에서 확인되듯, Gemini는 application/pdf MIME 타입을 사용하여 PDF 문서를 직접 입력받아 분석한다. 이에 따라 본 프로젝트는 모든 PDF를 이미지로 일괄 변환하는 방식 대신 원본 문서 형식을 활용하는 입력 방식을 적용하였다. 이는 불필요한 파일 변환을 줄이면서 모델이 공식 지원하는 문서 처리 인터페이스를 활용한 설계이다."

[추가 실제 프로젝트 증빙 권장]
- 실제 API 요청의 MIME 타입이 application/pdf인 코드 또는 로그
- PDF 원본 파일 → 모델 응답 → 최종 추출 데이터 화면
- 이미지 입력 시 image/jpeg 또는 image/png로 전달되는 분기 코드가 있다면 함께 제출
- 실제 구현과 다르게 '모든 파일에 MIME 분기 적용' 같은 표현은 사용하지 말 것

4. 데이터 포맷 표준화 - 텍스트 기반 PDF 사용 권장 (핵심 증빙)
======================================================================
[공식 홈페이지]
제목: 문서 이해 (위의 3번과 동일)
URL: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/document-understanding?hl=ko

[홈페이지에서 캡처할 내용]
캡처명: 04_PDF_권장사항.png
페이지 내 Ctrl+F 검색어: PDF 권장사항
캡처 범위:
  - 'PDF 권장사항' 제목
  - '스캔한 이미지에 텍스트를 사용하는 대신 텍스트로 렌더링된 텍스트로 생성된 PDF를 사용합니다.'라는 권고
  - 기계가 읽을 수 있는 텍스트 및 텍스트가 많은 문서에 대한 설명

[의미 / 기술 설명]
Google은 이미지 기반 스캔 PDF보다 기계 판독이 가능한 텍스트 기반 PDF를 권장한다.
텍스트 레이어가 있는 원본 PDF를 전부 이미지로 변환하면 그 텍스트 레이어가 소실될 수 있으므로 일괄 이미지 변환이 최적이라고 일반화할 수 없다.
단, 모든 PDF가 이미지보다 정확하다는 의미는 아니다. 스캔 PDF와 디지털 PDF를 구분해야 한다.

[제출 설명 - 붙여 넣기용]
"Google Cloud는 텍스트 기반 PDF를 문서 이해 작업에 권장하고 있다. 이에 본 프로젝트는 원본 PDF의 텍스트 정보가 유지될 수 있도록 불필요한 이미지 변환을 배제하고, Gemini에서 지원하는 PDF 직접 처리 방식을 우선 활용하도록 설계하였다."

[추가 실제 프로젝트 증빙 권장]
- 텍스트 레이어가 포함된 PDF 샘플(개인정보 비식별화)
- 동일 PDF의 원본 입력 vs 이미지 변환 입력 비교 결과(있을 경우)
- 인식률 우위 주장은 실제 비교 지표가 확보됐을 때만 기재

5. 추출 결과 포맷의 표준화(JSON) - 선택 증빙
======================================================================
※ 원 요구사항의 '데이터 포맷 표준화'가 입력 문서를 이미지 형식으로 통일하라는 뜻이었다면
   이 항목은 요구사항의 직접 증빙이 아니다. 추출 결과를 JSON으로 통일하는 기능을
   실제 구현한 경우에만 보조 자료로 사용한다.

[공식 홈페이지]
제목: 구조화된 출력 (Structured output) / Google Cloud 공식 문서
URL: https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/control-generated-output?hl=ko

[홈페이지에서 캡처할 내용]
캡처명: 05_JSON_스키마.png
페이지 내 Ctrl+F 검색어: 사용 사례
캡처 범위:
  - '구조화된 출력' 문서 제목과 응답 스키마 설명
  - '사용 사례' 절의 JSON과 스키마 설명
  - Python 예제의 response_mime_type="application/json", response_schema=... 설정 부분

[의미 / 기술 설명]
Gemini는 응답 JSON 형식과 필드 구조를 스키마로 제어하는 기능을 지원한다.
단순히 프롬프트에 JSON을 요청하거나 response_mime_type만 설정한 경우와
response_schema를 함께 사용한 경우는 구분해야 한다.

[제출 설명 - 붙여 넣기용]
"Google Cloud는 Gemini 응답의 구조화된 출력을 위한 JSON MIME 타입 및 응답 스키마 설정을 지원한다. 본 프로젝트에서 해당 기능 또는 별도의 후처리 검증 로직을 적용한 경우, 추출 결과를 일관된 데이터 구조로 제공하는 근거로 사용할 수 있다."

[추가 실제 프로젝트 증빙 권장]
- 실제 response_schema 설정 코드 또는 JSON 직렬화/유효성 검사 로직
- 동일 문서 유형의 여러 추출 결과에서 필드 구조가 유지됨을 보여주는 화면
